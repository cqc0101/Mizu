# 原始 get_battery.py 审查

原始文件备份为 `get_battery.original.py`。不在旧脚本上继续叠加 GUI；新的采集层在 `src/Mizu.Core`。

1. `send_and_wait` 只比较 `resp[1]` 槽位。设备通知、其他程序的请求回复、之前请求的迟到消息均可能被误收。新实现核对报表 ID、设备索引、feature、function/software ID；每笔请求轮换软件 ID，过滤错误帧。
2. 设备类型查询使用 `0x20`，software ID 为 0。新实现所有请求使用非零软件 ID，并保留协议规定的函数编号。
3. 注释写了 `0x1004 / 0x1000`，实际只有 `0x1004`。新实现补充 `0x1000` 及充电状态，对粗略档位不虚构精确百分比。
4. 仅处理 HID++ 1.0 风格 `0x8F` 错误，遗漏 HID++ 2.0 的 `0xFF` 错误。新实现严格校验并排除两种错误。
5. 仅枚举 usage FF00/02，且未根据 HID 报表能力打开和填充准确长度。新实现枚举原生 HID 能力、选择长报表通道，并按接口声明长度传输；短报表专用设备明确不宣称支持。
6. 接收器固定扫描 1–6，漏掉 FF 直连路径。新实现增加 FF，并通过协议版本 ping 检测是否支持 HID++ 2.0。
7. 品牌词 `atk`、`vgn` 或短型号 `a9` 不能可靠证明鼠标类型。新实现优先 HID usage、容器子设备类型与厂商协议类型；设置可手动纠正。
8. 通过名称去重会吞掉同名设备。新实现使用物理容器 / 哈希身份 + 接收器槽位，不能证明同一设备时保持独立。
9. 每次检测启动 PowerShell，成本高，编码和异常处理不稳定。新实现直接 SetupAPI / HID P/Invoke，不启动子脚本采集。
10. 仅扫描 `BTHLE` 节点会遗漏部分经典蓝牙和 HID 子节点上报的电量。新实现关联 Bluetooth / HID 容器；缓存电量与未知连接状态明确区分。
11. 把罗技 HID++ 路径当作“所有 2.4G”不成立。ATK 采用独立协议；未适配厂商不会被猜测性探测。
12. 大范围 `except: pass` 隐藏了设备打开失败、协议错误和超时。新实现分离 provider 失败、保留无密钥的诊断，UI 不因设备异常卡住。

尚未实现：旧 HID++ 1.0、电压曲线估算、所有厂商的私有 HID 协议、直接 BLE GATT 读取。不把这些能力写成已完成。
